# Messages, Tasks, and Artifacts

This page provides details about the core concepts of the A2A protocol implementation in the Koog agentic framework: Messages, Tasks, Artifacts, and Parts.

## Messages

Messages are the primary means of communication between clients and agents in the A2A protocol. They represent individual exchanges in a conversation.

### Structure

A message is represented by the `Message` class. Here are the key properties of the `Message` class:

| Name                 | Description                                                                    |
|----------------------|--------------------------------------------------------------------------------|
| **messageId**        | The unique identifier for the message                                          |
| **role**             | Identifies the sender (`User` or `Agent`)                                      |
| **parts**            | The content of the message, which can include text, files, and structured data |
| **extensions**       | URIs of extensions relevant to this message                                    |
| **taskId**           | The ID of the task this message is part of                                     |
| **referenceTaskIds** | IDs of other tasks referenced by this message                                  |
| **contextId**        | The context ID for grouping related interactions                               |
| **metadata**         | Optional metadata for extensions                                               |

### Message roles

Messages can be sent by either `User` (client) or `Agent` (server):

### Creating messages

To create a user message:

```kotlin
val userMessage = Message(
    role = Role.User,
    parts = listOf(TextPart(text = "Hello, agent!"))
)
```

## Tasks

Tasks represent stateful operations or conversations between clients and agents. They encapsulate the entire lifecycle of an interaction, from initiation to completion.

### Structure

A task is represented by the `Task` class. Here are the key properties of the class:

| Name          | Description                                                        |
|---------------|--------------------------------------------------------------------|
| **id**        | The unique identifier for the task                                 |
| **contextId** | The unique identifier for maintaining context across related tasks |
| **status**    | The current status of the task                                     |
| **history**   | The conversation history (messages exchanged during the task)      |
| **artifacts** | Outputs generated by the agent during the task                     |
| **metadata**  | Optional metadata for extensions                                   |

### Task status

The status of a task is represented by the `TaskStatus` class. Here are its key properties:

| Name          | Description                                                         |
|---------------|---------------------------------------------------------------------|
| **state**     | The current state of the task's lifecycle                           |
| **message**   | An optional message providing more details about the current status |
| **timestamp** | When this status was recorded                                       |

### Task states

Tasks can be in various states throughout their lifecycle. The `TaskState` enum class represents the possible task states, where each state includes the `terminal` boolean property. 
Terminal states indicate that the task has reached its end and will not change further.

Here is the `TaskState` class with all constants that represent a possible state in a task's lifecycle:


```kotlin
public enum class TaskState(public val terminal: Boolean) {
    Submitted(terminal = false),
    Working(terminal = false),
    InputRequired(terminal = false),
    Completed(terminal = true),
    Canceled(terminal = true),
    Failed(terminal = true),
    Rejected(terminal = true),
    AuthRequired(terminal = false),
    Unknown(terminal = false),
}
```

### Task events

The A2A protocol defines several events related to tasks:

- `TaskStatusUpdateEvent`: notifies the client of a change in a task's status.
- `TaskArtifactUpdateEvent`: notifies the client that an artifact has been generated or updated.

## Artifacts

Artifacts are outputs generated by agents during task execution. They can represent documents, images, code snippets, or any other type of content.

### Structure

An artifact is represented by the `Artifact` class. Here are the key properties of the class:

Key properties:

| Name           | Description                                                  |
|----------------|--------------------------------------------------------------|
| **artifactId** | A unique identifier for the artifact                         |
| **type**       | The type of the artifact such as "document", "image", "code" |
| **parts**      | The content of the artifact                                  |
| **metadata**   | Optional metadata for the artifact                           |

### Creating artifacts

Here is an example of how you can create an artifact:

```kotlin
val artifact = Artifact(
    type = "document",
    parts = listOf(
        TextPart(text = "This is a document"),
        FilePart(
            file = FileWithBytes(
                bytes = Base64.encode(byteArrayOf(/* ... */)),
                name = "document.pdf",
                mimeType = "application/pdf"
            )
        )
    )
)
```

## Parts

Parts are the building blocks of messages and artifacts. They represent different types of content that can be exchanged between clients and agents.

### Structure

A part is represented by the `Part` interface. Depending on the type of content in the part, there are the following types of parts:

- `TextPart`
- `FilePart`
- `DataPart`

#### TextPart

Represents plain text content:

```kotlin
public data class TextPart(
    public val text: String,
    override val metadata: JsonObject? = null,
) : Part
```

#### FilePart

Represents file content:

## Putting it all together

Here is an example of all concepts described on this page work together in a typical A2A interaction:

1) The client sends a message to the agent:

```kotlin
val userMessage = Message(
    role = Role.User,
    parts = listOf(TextPart(text = "Generate a report on climate change"))
)

val request = Request(
    data = MessageSendParams(message = userMessage)
)

val response = client.sendMessage(request)
```
<!--- KNIT example-a2a-messages-tasks-artifacts-13.kt -->

2) The agent processes the message and creates a task:

```kotlin
val task = Task(
    id = "task-123",
    contextId = "context-456",
    status = TaskStatus(
        state = TaskState.Working,
        message = Message(
            role = Role.Agent,
            parts = listOf(TextPart(text = "I'm working on your report...")),
            taskId = "task-123",
            contextId = "context-456"
        )
    )
)
```
<!--- KNIT example-a2a-messages-tasks-artifacts-14.kt -->

3) The agent generates an artifact and updates the task:

```kotlin
val artifact = Artifact(
    artifactId = "artifact-789",
    type = "document",
    parts = listOf(
        TextPart(text = "# Climate Change Report\n\nThis report covers..."),
        FilePart(
            file = FileWithBytes(
                bytes = Base64.encode(byteArrayOf(/* ... */)),
                name = "climate-report.pdf",
                mimeType = "application/pdf"
            )
        )
    )
)

val updatedTask = task.copy(
    status = TaskStatus(
        state = TaskState.Completed,
        message = Message(
            role = Role.Agent,
            parts = listOf(TextPart(text = "I've completed your report on climate change.")),
            taskId = "task-123",
            contextId = "context-456"
        )
    ),
    artifacts = listOf(artifact)
)
```
<!--- KNIT example-a2a-messages-tasks-artifacts-15.kt -->

4) The client retrieves the completed task:

```kotlin
val request = Request(
    data = TaskQueryParams(taskId = "task-123")
)

val response = client.getTask(request)
val completedTask = response.data
```
