# A2A protocol

This page provides an overview of the A2A (Agent-to-Agent) protocol implementation in the Koog agentic framework.

## What is the A2A protocol?

The A2A (Agent-to-Agent) protocol is a standardized communication protocol that enables AI agents to interact with each other and with client applications. It defines a set of methods, message formats, and behaviors that allow for consistent and interoperable agent communication.

The A2A protocol is designed to facilitate:

- Structured communication between clients and agent services
- Long-running, asynchronous tasks
- Streaming of partial results
- Push notifications for task updates
- Standardized error handling

For more information and a detailed specification of the A2A protocol, see the official [A2A Protocol website](https://a2a-protocol.org/latest/).

## Key components

The Koog implementation of the A2A protocol consists of the key components whose details are in the sections below.

### A2A client

The A2A client is responsible for sending requests to A2A servers. It handles the following tasks:

- Connecting to agent services
- Retrieving agent capabilities via Agent Cards
- Sending messages to agents
- Managing tasks and their lifecycle
- Receiving streaming updates
- Configuring push notifications

### A2A server

The A2A server processes requests from A2A clients and executes agent logic. The A2A server performs the following functions:

- Processing client requests
- Executing agent logic via the AgentExecutor
- Managing task state and lifecycle
- Streaming partial results
- Sending push notifications
- Error handling and reporting

### Agent Cards

Agent Cards describe the capabilities and metadata of an agent service. An Agent Card includes the following information about an agent:

- Basic agent information (name, description, version)
- Supported agent capabilities (streaming, push notifications)
- Authentication requirements
- Extended capabilities

### Transport layer

The transport layer handles the actual communication between clients and servers. 
Koog supports JSON-RPC transport.

## Core concepts

The following sections provide basic information about the key concepts and building blocks of communication through the A2A protocol, and their specific implementation in Koog.

### Message

A message represents a single unit of communication between a user and an agent. Messages contain the following information:

- A unique message ID
- The sender's role (user or agent)
- Content parts (text, files, structured data)
- Optional metadata

### Task

A task represents a stateful operation or conversation between a client and an agent. Tasks include the following data:

- A unique task ID
- A context ID for related interactions
- Current status information
- Message history
- Generated artifacts

### Artifact

Artifacts are outputs generated by agents during task execution, such as:

- Documents
- Images
- Code snippets
- Structured data

### Parts

Parts are the building blocks of messages and artifacts. The A2A protocol supports the following types of parts:

- Text parts (plain text content)
- File parts (binary data or file references)
- Data parts (structured data like JSON)
